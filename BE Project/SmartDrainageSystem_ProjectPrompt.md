## 🤖 ML PIPELINE (HOW THE AI WORKS)

1. **Data Source**: 8 PCMC locations with sensor fields:
   - `rainfall_mm_hr`, `water_level_m`, `drain_capacity_percent`
   - `temperature_c`, `humidity_percent`, `flow_rate_m3s`
   - `sewer_overflow_risk_percent`, `flood_risk` (label)

2. **Model Architecture — Hybrid CNN-LSTM + XGBoost**:
   - Input: last 12 timesteps × 3 features (rainfall, drain_capacity, water_level)
   - CNN-LSTM extracts deep temporal features
   - XGBoost makes final flood risk classification
   - Output: risk = LOW / MEDIUM / HIGH + probability + confidence

3. **Flood Risk Rules**:
   - `water_level >= 3.5m` OR `rainfall >= 100mm` → **HIGH**
   - `water_level >= 2.0m` OR `rainfall >= 60mm` → **MEDIUM**
   - Otherwise → **LOW**

4. **Model Files** (in `backend/trained_models/`):
   - `cnn_lstm_model.h5` — Keras model
   - `xgb_model.json` — XGBoost model
   - `scaler.pkl` — sklearn scaler

## 🔄 REAL-TIME DATA FLOW

1. `data_generator.py` runs as a background thread on startup
2. Generates new sensor rows every **30 seconds** for all 8 PCMC locations
3. Writes to `backend/data/live_sensor_data.csv`
4. `/api/live-data` reads the last 60 rows from this CSV
5. WebSocket `/ws/sensors` streams live sensor updates to the frontend
6. Dashboard polls or receives updates and re-renders charts and stat cards

---

## 🔐 AUTHENTICATION FLOW

1. User registers via `/auth/signup` → bcrypt-hashed password stored in MySQL
2. User logs in via `/auth/login` → receives JWT token
3. Token stored in `AuthContext` (frontend)
4. `ProtectedRoute` component guards dashboard pages
5. Token sent in `Authorization: Bearer <token>` header for protected API calls

## 📌 IMPORTANT NOTES FOR AI ASSISTANT

1. The backend entry point is `app.main:app` — always run with uvicorn from inside `backend/`
2. The `.env` file must be inside `backend/` (not the project root)
3. ML models must be in `backend/trained_models/` — the predict.py resolves paths relative to itself
4. The live CSV path is `backend/data/live_sensor_data.csv` — auto-created on startup
5. `App.jsx` keeps all route definitions even if nav buttons are hidden — never delete routes
6. The Chatbot component is rendered globally in `App.jsx`, outside all layouts
7. WebSocket runs on `ws://localhost:8000/ws/sensors`
8. Frontend API base URL is controlled by `VITE_API_URL` in `.env` (frontend)
9. MySQL database is required (not SQLite) — update `DATABASE_URL` accordingly
10. Twilio and Groq keys are optional for basic functionality (SMS and chatbot degrade gracefully)
